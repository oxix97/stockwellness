# 백엔드 작업과 Git

- 관련 Issue가 있으면 범위와 인수 조건을 확인한다. Issue가 없어도 승인된 작업을 진행하며 원격 등록은 요청된 경우에만 한다.
- 작업 전 `git status`로 기존 변경을 확인하고, 기술 버전과 명령은 Gradle 설정을 따른다.
- 금융·인증·API 경계와 실패 경로를 검증하고 관련 신규 코드의 커버리지 목표는 [테스트 기준](testing.md)을 따른다. API 변경은 REST Docs와 OpenAPI 및 소비자 호환성을 확인한다.
- 커밋 메시지는 한글로 작성하고 정확한 메시지와 포함 파일을 승인받는다. Issue·PR·push·머지·배포는 요청 범위에 따라 별도로 처리한다.
- PR 대상과 머지 방식은 당시 실제 저장소 설정을 확인한다. 커밋·Issue 종료·머지와 구현 완료는 별도 상태로 보고한다.
- 배포는 별도로 승인된 경우 실제 인프라 지침과 대상 환경을 확인한다. 실행 명령을 예시로 보았다는 사실은 배포 승인이 아니다.
