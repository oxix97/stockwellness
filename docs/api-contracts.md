# API 계약 및 소비자 호환성

- 실제 컨트롤러, DTO, 테스트 및 생성된 문서를 확인해 계약을 판단한다.
- 기존 표준 응답 래퍼, `GlobalException(ErrorCode)` 규칙을 우선 적용한다.
- 입력 검증, 인증/인가, 오류 코드, 페이징 및 필드의 null 허용 여부를 확인한다.
- 프론트엔드 연동 시 날짜 의미, 금액 단위, 수익률 정밀도, 필드명, 오류 형태를 계약으로 정의한다.
- API 응답 또는 오류 의미 변경 시 REST Docs와 OpenAPI 출력/소비자 호환성을 검증한다.

관련 외부 참조: 최상위 PO 작업 공간의 `../docs/specs/screen-api-mapping/README.md` (해당 경로가 실제 존재할 때만 참고).
